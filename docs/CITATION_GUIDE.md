## GitHub citation metadata

The repository contains `CITATION.cff` at its root.

GitHub can use this file to expose a **Cite this repository** interface and machine-readable citation metadata.

The CFF now records:

```text
version: 1.1.0
date-released: 2026-09-02
doi: 10.5281/zenodo.22257814
license: MIT
```

## Exact reproducibility

When reproducing an experiment, cite the exact archived software release DOI and record the exact Git commit when possible.

## Software versus dataset citation

The software repository and generated datasets are conceptually different research objects.

A paper using:

- generator implementation should cite the software release
- a specific generated dataset should cite that dataset record if it later receives its own DOI
- both software and dataset should cite both objects when both materially contribute

## Future versions

Future releases archived by Zenodo can receive version-specific DOIs.

Do not overwrite the meaning of this v1.1.0 DOI.

## Preferred citation

If a peer-reviewed paper or formal technical report later becomes the canonical scholarly description of this research, `CITATION.cff` can use `preferred-citation` while retaining the software metadata.
